**Change ID:** `20261114-animecream-g14-g15`

## Summary
Two bugs found while raising the coverage gate (`20261114-animecream-coverage-100`). The owner chose to fix both:
- **G14:** a swipe between tabs no longer gets lost when the app re-renders during the swipe.
- **G15:** a series answer that is neither a list nor `{ data: list }` is now a load error. Before, it broke
  the page.

## G14, `src/hooks/useSwipeableTabs.js`
**Before:** `startX` was a plain `let` inside the hook. Each render creates new handlers with a new, empty
`startX`, so a re-render between touch start and touch end made the touch end compute `endX - undefined`
(`NaN`), and the swipe did nothing.

**After:** the start lives in `useRef(null)`, as in Finanz's twin hook. A touch end with no recorded start still
does nothing, now through the explicit `null` check.

| Case | Before | After |
|---|---|---|
| Swipe without a re-render | Changes tab | Same |
| Swipe with a re-render between start and end | Nothing | Changes tab |
| Touch end with no start, or a second end | Nothing | Same |
| Swipe that starts on a range input | Nothing | Same |

## G15, `src/Components/Home/Home.jsx`
**Before:** on the initial load and on a search, any answer without `err` was taken as the catalog
(`productionsInfo.data || productionsInfo`). An object, `{ data: null }` or a string was stored in `db`, and the
initial load also cached it. The page then failed to render. An empty answer (`null`) on a search threw outside
any `try`, so the loader stayed on screen. The list-by-ids paths already failed into their `catch`.

**After:** a new helper, `readSeriesList`, accepts only a list or `{ data: list }` and returns `null` for
anything else.

| Load | Unexpected answer, before | Unexpected answer, after |
|---|---|---|
| Initial catalog | Cached, page breaks | Not cached; the bundled seed or cached catalog stays; "Error loading data" |
| Search / filter (`opt`) | Page breaks (object) or stuck loader (`null`) | Series shown stay; loader closes; "Error loading data"; a full-catalog request caches nothing |
| List by ids (My Lists) | "Error loading series by IDs" | Same |
| Shared list route `/list/…` | "Error loading data" | Same |

Valid answers (a list, `{ data: list }`) and API errors (`{ err }`) behave as before.
