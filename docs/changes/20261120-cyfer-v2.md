# Cyfer version 2, the shared library

**Date:** 2026-11-20 · **Branch:** `feature/20261120-cyfer-v2` · **Released in:** production 2026-11-20 (from the branch, merged 2026-11-20)
**Implements:** the shared cyfer library, `module-docs/apps/bitacora/SPEC.md` v1.18.4 §2.13, D40 (P77).
`module-docs/apps/animecream/SPEC.md` does not mention cyfer, so it does not change.
**Change ID:** `20261120-cyfer-v2` (also in bitacora-react, finan-react, module-api and cyfer-vanilla)

## Summary
`src/helpers/cyfer.js` is replaced by the owner's cyfer version 2, the same file in every project
(home: `github.com/anderOkgo/cyfer-vanilla`, `dist/js/cyfer.js`). The only call site,
`src/services/auth.service.js`, does not change: `cyfer().cy` / `dcy` keep working, now as synchronous
version 2 (UTF-8 bytes, a random nonce, a SHA-256 key stream, a 4-byte check). A value that does not
open gives `null` instead of throwing.

## Behavior by case
| Case | Now |
|---|---|
| The session in `localStorage` | Stored with version 2 |
| A session stored before this change | Gives `null`: the user logs in once more |
| A stored session that opens but is not JSON | Logged and `null` (the existing `catch`) |

## Decisions
- **D1 — Same call shape:** the library's default export `cyfer()` returns `{ cy, dcy, cyAsync,
  dcyAsync }`; Animecream uses the synchronous pair (owner, Bitácora P77).
- **D2 — Tests:** the library's own tests replace `src/helpers/__tests__/cyfer.test.js`. One new test in
  `auth.service.test.jsx` covers a session that opens but is not JSON. Garbage no longer reaches the
  `catch`, because it gives `null` quietly.
